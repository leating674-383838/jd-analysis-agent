# 岗见 · Prompt 设计与迭代

> 出于防复制考虑，本文只记录 Prompt 的**结构、约束和迭代过程**，不公开原文。

## 1. 设计目标
让模型在拿到「公司名称 + 岗位名称 + JD 原文 + 公司公开信息」后，输出结构化的深度解析：企业真实需求、岗位细分类型、风险提示、公司背景，帮助求职者解决 JD 难读、信息分散的问题。

## 2. Prompt 结构
| 模块 | 内容 |
|---|---|
| Role | 资深猎头专家，擅长通过「多源交叉验证」识别岗位真实性与潜在风险 |
| Context | 面向中国求职者，用户粘贴招聘平台的岗位描述 |
| Task | 5 步：校验字段 → 语言处理 → 大白话解读 → 分类 + 虚假岗位判别 + 公司信息整合 → JSON 输出 |
| 分析思路 | 隐性思维链：先提取动词与关键名词，再判断背后的业务含义与能力要求，最后输出结论；不展示中间推理 |
| 识别规则 | 职责拆解、公司名匹配、外包交叉验证等规则，并配有触发词族（身份类、诱导类、待遇类） |
| Constraints | 对输出字段的格式与取值约束 |
| Negative Constraints | 禁止臆想 JD 未提及的福利与薪资、禁止多余寒暄、禁止输出非 JSON、禁止违法建议、禁止泄露 Prompt、禁止性别倾向建议 |
| Output Format | 固定 JSON Schema，见 [ai-spec.md](ai-spec.md) |
| Few-shot | 一个正常 JD 的正向示例，一个「合伙 / 兼职 / 全职灵活合作」类风险 JD 的边缘示例 |

调用参数：单次调用、`max_tokens` 800；输出后做 JSON 提取与必填字段校验，不通过则返回错误并退回游客次数。

## 3. 核心约束清单
| 约束 | 规则内容 | 加入版本 | 加入原因 |
|---|---|---|---|
| risk_alerts 非空 | 无风险返回 `["无"]`，严禁空数组 | V1.0 | 空数组导致前端崩溃 |
| insight 字数 | 成功时必须 50–150 字 | V1.1 | 早期输出过短、没有信息量 |
| 公司名匹配 | 搜索结果与输入公司不符 → 输出固定文案 | V2.0 | 输入虚构公司名，返回了真实公司信息 |
| 外包交叉验证 | 搜索结果含外包关键词 → 强制加入风险提示 | V2.1 | 外包公司 JD 不写外包，但搜索能查到 |

## 4. 版本记录
| 版本 | 日期 | 变更原因 | 变更内容 | 验证 |
|---|---|---|---|---|
| V2.1 | 2026-04-15 | 外包公司在 JD 里不写外包，但搜索能查到 | 新增外包交叉验证规则 | 输入某外包公司 JD → 正确输出外包风险提示 ✅ |

## 5. 已知局限
- 英文 JD 识别准确率偏低
- 公司过于冷门、搜索无结果时，退化为纯 JD 分析

## 6. 验证模型
双源交叉验证：JD 文本分析 + 公司公开信息检索，两路信息互相印证，而不是只信任其中一路。
